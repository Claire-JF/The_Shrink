## Backend-2 — AI 逻辑层（provider-agnostic）

**Owner of:** `llm/client.js`、`scorer.js`、`optimizer.js`、`schema.js`、`fallback.js`、`warmup.js`、`stability-test.js`

### 核心责任

让"一段文字进来 → 5 维分数出去"和"一段文字 + 分数进来 → 优化版出去"这两件事 100% 可靠，**不管底层用的是哪家 LLM**。

### 任务清单

| 时间 | 任务 |
|------|------|
| 11:30 | `llm/client.js` 接口定义：`call(model, prompt, opts) → Promise<string>`。先写一个 mock 实现返回 hardcoded JSON |
| 12:00 | 选定 LLM provider，写真实 client 实现（OpenAI-compatible 通用模板，CLōD 直接能用，OpenAI 也能用）|
| 12:30 | scoring prompt 第一版：用 **checklist 格式**，5 个维度每个写明确判定规则 |
| 13:00 | `scorer.js` 跑通：输入文本 → 输出 score JSON。`schema.js` 验证、`fallback.js` 容错 |
| 13:30 | 稳定性初测：同一个 prompt 跑 5 次，total 分数方差 < 0.3 |
| 14:00 | optimization prompt 第一版；`optimizer.js` 跑通 |
| 14:30 | 两个 demo prompt 手工挑定（vague + danger），写进固定的测试 fixture |
| 15:00 | `warmup.js`：app 启动时调一次任意请求，预热连接 |
| 15:30 | **`stability-test.js`：独立脚本，两个 demo prompt 各跑 20 次，输出每次分数。要求 vague 全部 < 2.5，danger 全部 < 1.0** |
| 16:00 | 如果 stability test 不过，回头改 scoring prompt 加更严的 checklist，再跑 20 次 |
| 16:30+ | 性能优化：scoring 调用缩短到 < 1.5s（换更快的 model 或精简 prompt）|

### 关键约定

- **client 抽象不能漏**：所有 `scorer.js` 和 `optimizer.js` 都通过 `llmClient.call()`，永远不直接 fetch
- **temperature 0 on scoring**，0.2 on optimization
- **prompt 用 checklist 不用自由判断**，这是稳定性的最大杠杆
- **永远返回有效对象**，解析失败走 fallback

### 暴露给 Backend-1 的接口

```typescript
scorer.score(text): Promise<ScoreJSON>
optimizer.optimize(text, scoreResult): Promise<OptimizedJSON>
warmup.warmup(): Promise<void>  // 启动时调一次
```

## LLM provider 抽象的具体好处

```javascript
// llm/client.js
class LLMClient {
  constructor(config) {
    this.baseURL = config.baseURL;     // 换 provider 改这里
    this.apiKey = config.apiKey;
    this.headers = config.headers;
  }
  async call(model, prompt, opts) { /* 通用实现 */ }
}

// config.js
export const llmConfig = {
  baseURL: process.env.LLM_BASE_URL,    // CLōD / OpenAI / Anthropic 改 .env 就行
  apiKey: process.env.LLM_API_KEY,
  fastModel: process.env.LLM_FAST_MODEL,
  deepModel: process.env.LLM_DEEP_MODEL
};
```

**好处：**
1. 今天上午先用 OpenAI 把流程跑通（如果 OpenAI key 团队已有），下午再切 CLōD 也只是改 .env
2. 现场 CLōD 出问题（rate limit、网络）能秒切回 OpenAI
3. Backend-2 不用等 sponsor 那边的事情确认，可以提前开干
